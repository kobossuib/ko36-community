# KO-36 Community

Report bugs, suggest improvements and follow development of KO-36. Español / English welcome.

- [Reportar un fallo / Report a bug](https://github.com/kobossuib/ko36-community/issues/new?template=bug.yml)
- [Proponer una mejora / Suggest an improvement](https://github.com/kobossuib/ko36-community/issues/new?template=idea.yml)
- [Ver reportes / Browse reports](https://github.com/kobossuib/ko36-community/issues)

The no-account web form is being deployed. These GitHub forms require a GitHub account.

## How it works / Cómo funciona

Report → review → ready → development → device testing → release → published.

Every report enters the KO-36 intake queue. Maintainers verify bugs and prioritize work; product changes need an accepted scope. An open report is not a delivery promise. Firmware fixes remain open until tested on hardware and included in a published release.

Issues and their attachments are public. Do not include passwords, private projects, email addresses, serial numbers or full logs. Use links to screenshots or short videos with no personal information.

Independent testers can reproduce existing reports and add their version and steps. Developers can propose a change in an issue; PRs here are for this portal and its documentation. Firmware source access is separate and is not granted by opening an issue.

See [contribution guide](CONTRIBUTING.md) and [operations](docs/operations.md).
